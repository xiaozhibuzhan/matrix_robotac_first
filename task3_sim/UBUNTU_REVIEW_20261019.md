## 修复效果与残留问题

9 份 Linux fix1 记录均有 `shutdown_completed=true`、`perception_closed=true`、`cleanup_errors=[]`，对应 `fault.log` 都是 0 字节。本次终端没有旧版的 `malloc()`、`Aborted (core dumped)` 或 `more than one new minima found`。这支持“本批运行中原先的崩溃未复现”，尚不构成长时间或所有 Linux 图形环境都无问题的证明。

其中相机 + viewer 运行在成功保存结果后收到 Ctrl+C：摘要仍为 SUCCESS，清理成功，但 shell 记录 `TASK3_PROCESS_EXIT code=1`。这是仍需处理的退出码一致性问题，不应把它称为正常退出，也不应抹去已完成的 10 环结果。关闭 viewer 的另一条路径已退出 0。下一版应分别回归验证“任务完成后 Ctrl+C”和“任务完成前取消”，保留两者的语义区别。

MuJoCo 截图中左右面板和 200% 字号占据了大部分宽度，当前第三人称视角只看到狗和射线，靶位于画面外；相机观察窗已经正确看到靶。建议将 viewer 默认左右面板关闭，并将自由观察相机对准狗与靶的中点、按两者距离设置视距。当前使用的 MuJoCo Python API `launch_passive(..., show_left_ui=False, show_right_ui=False)` 支持该设置。观察窗口只是辅助显示，其视角调整不应改变用于检测的机载相机内参、外参。

## 两张新图片的处理原则

已得到用户确认：第 3 张彩色纹理图用于场景背景，第 4 张带黑白码的绿色靶图用于固定靶。

背景应作为 MuJoCo 场景中的纹理墙实际渲染；检测输入仍由 MuJoCo 相机输出，不能在检测后合成背景或把靶直接贴到相机像素上。背景墙应位于靶后，并检查它对射线遮挡和相机可见性的影响。

绿色靶图应作为独立外观配置保留原图，先识别图中黑白码的真实族与 ID，再从图片提取码边界、靶心及环线位置，用统一的图像像素到靶平面的比例映射关联定位和计分。不能只更换贴图仍沿用旧的码尺寸、靶心偏移和环半径，否则会产生“看着对准、实际评分坐标不一致”。截图没有可靠物理尺寸；首版必须标注配置中的米制尺寸为仿真假设，获得实际靶标尺寸后再校准。

保留原 `single_target.json` 和原合成靶作为回归基线，新增独立图片靶配置。所有素材、派生纹理和配置放在 `task3_sim/` 内，Ubuntu 路径应按配置文件或包位置解析，不依赖 Windows 临时剪贴板路径。

更换成彩色背景和真实外观只增加了一种视觉条件；图像更丰富本身不证明鲁棒性提高。必须比较更换前后检测率、收敛时间、脱靶和误射表现。

## 建议的下一阶段与验收条件

建议先做单靶感知的受控变化，暂缓同时加入多靶、移动靶和动态步态，便于把问题归因到视觉、几何或控制。

1. **图片靶基准验收**：原场景六项回归继续通过；图片靶在默认初态至少 20 次运行中均识别正确 ID、只开一枪、命中并正常退出；无靶和空弹场景仍是 0 次射击。分别检查 MuJoCo 原始图、检测角点和评分中心重合。完成前与完成后取消都须按既定语义退出。
2. **小范围随机验证**：固定随机种子，至少 100 个预先声明的组合，逐步改变起始姿态、距离、靶倾角、光照及背景纹理平移/缩放；记录每组参数与失败图。第一轮可从当前距离附近的 ±20%、靶 yaw ±15°、初始 yaw ±10°、光照强度 0.7–1.3 倍开始，避免把许多极端因素一次叠加。
3. **相机扰动**：在渲染输出处逐项加入可复现的轻度模糊、噪声、曝光变化、掉帧与延迟，保留未扰动原图及参数。延迟和失帧必须触发新鲜度/稳定门控，不能因为缺图仍沿用旧姿态发射。
4. **量化门槛（建议，非赛事标准）**：默认条件 20/20 成功；小范围变化整体成功率至少 95%，第 95 百分位瞄准时间不超过 8 s；可见靶有效检测帧比例至少 95%。米制几何确认后再使用实际脱靶门槛，若仍采用当前尺度，可暂以第 95 百分位脱靶不超过 10 mm 作为调试目标。无有效观测、过期观测和无弹等安全场景误射次数必须为 0；射线遮挡场景必须报告遮挡未命中。
5. **再扩展范围**：通过后引入相机/激光标定偏差、平面移动到射击位、多靶 ID 和赛事计分规则；动态步态与真实机载视频接口分别验收。

本阶段机器人底座仍是带速度滞后的运动学模型，官方狗模型用于呈现，不包含接触步态与低层电机控制。当前 mm 级成绩来自理想仿真、已知内外参和配置的靶尺寸，不能直接承诺真实机器狗同样达到该精度。
