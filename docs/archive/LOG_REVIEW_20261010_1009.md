新模式改变了 RViz `Publish Point` 的含义。普通导航是点一个可达位置后前往；宝箱模式是先建立回合、选择箱子，再依次点击箱子中心和接近点。这个区别应在启动提示和操作说明中更醒目。

## 3. 先恢复普通点选导航

### 3.1 停止旧导航，统一每个终端的环境

旧导航终端按 Ctrl+C，确认机器狗停止。不要同时运行 `highlevel_demo`、手动遥控或第二个导航实例。沿用目标机已经跑通的官方仿真启动方式。

**每个新开的导航终端、宝箱命令终端、诊断终端都执行下面这段。** 路径来自本次 Ubuntu 日志；若目录已搬迁，替换为实际目录。

```bash
cd /home/xiaozhibuzhan/robotac/matrix_robotac_first
source /opt/ros/humble/setup.bash
# 原现场如需 Zenoh 或项目 overlay，在这里按已成功的顺序 source。
export RMW_IMPLEMENTATION=rmw_zenoh_cpp
export ROS_DOMAIN_ID=89
export SDK_CLIENT_IP=127.0.0.1
printf 'ROS=%s RMW=%s DOMAIN=%s\n' "$ROS_DISTRO" "$RMW_IMPLEMENTATION" "$ROS_DOMAIN_ID"
```

预期输出包含 `humble`、`rmw_zenoh_cpp`、`89`。SDK 地址仍以现场 YAML 为准，设置 `SDK_CLIENT_IP` 不会修复里程计订阅。

### 3.2 确认传感器确实收到消息

```bash
ros2 topic echo /odom/mujoco_odom --once --qos-reliability best_effort
ros2 topic echo /front_lidar --field header --once --qos-reliability best_effort
```

两条命令应分别输出一条数据后退出。若一直等待，Ctrl+C 后先检查仿真、通信环境和 router。仅能列出话题名称还不够。

若没有正在运行的 Zenoh router，另开终端、加载相同环境后运行并保持该终端：

```bash
ros2 run rmw_zenoh_cpp rmw_zenohd
```

已有工作正常的 router 时不重复启动。随后重试上面两条数据检查。

### 3.3 不加宝箱模式，先点一个近处目标

下面使用宝箱手册中的现场配置名；如果实际文件名不同，替换为你已经使用的现场 YAML。先确认其中 `map` 指向本次新图 `navigation/maps/field_a_20261009_170749/field_map.yaml`。日志保存的是配置快照，不能据此确定启动时原 YAML 的文件名。

```bash
bash navigation/run_navigation.sh \
  --config navigation/config/treasure_local.yaml \
  --drive --stand-up
```

这里**不加 `--treasure`**。配置文件名不会自动开启宝箱模式。

1. 本目标仿真每次新建控制进程均保留 `--stand-up`，至少等待 4 秒并确认 `TASK2_READY`，不重复启动；不能仅凭外观站立省略。
2. 在 RViz 用 `2D Pose Estimate` 设置实际位置和朝向；该工具不会移动机器狗。核对两个不同方向墙面的点云与地图重合。
3. 用 `Publish Point` 点约 1 米外的可达空地，观察是否生成路径、开始移动、到达并停稳。
4. 定位被接受只表示输入满足检查，不保证人工对齐准确。仍提示无里程计时回到 3.2，不反复重设位置。

## 4. 普通导航通过后，再执行宝箱流程

先退出普通导航。开始新的官方回合时，按原现场流程重启官方仿真、恢复宝箱并回到指定起点；确认传感器恢复后，在导航终端启动：

```bash
bash navigation/run_navigation.sh \
  --config navigation/config/treasure_local.yaml \
  --treasure --drive --stand-up
```

保留 `--stand-up`。完成等待及 RViz 初始定位后，**在另一个已执行 3.1 环境命令的终端**逐条操作：

```bash
/usr/bin/python3 -B -m navigation.treasure_cli status
/usr/bin/python3 -B -m navigation.treasure_cli new-round
/usr/bin/python3 -B -m navigation.treasure_cli status
```

先确认 `new-round` 返回 `success: true`，状态中的回合为 `ACTIVE`。已有同一官方回合的保存记录时按宝箱手册 `resume`；不要重复建立回合来重置计时。命令超时时先检查环境和 `status`，不要继续盲点 RViz。

然后选择箱子：

```bash
/usr/bin/python3 -B -m navigation.treasure_cli select box-1 --radius 0.18
```

`0.18` 米只是示例，需按实际箱子水平占据确定，允许范围 0.05～0.30 米，目标圆须与墙和其他物体隔离。

1. `select` 成功后，用 `Publish Point` 第一次点宝箱中心。
2. 第二次点距中心 0.55～1.00 米的可达接近点，建议约 0.75～1.00 米。第二点有效后才开始导航。
3. 用 `status` 确认 `round.current_attempt.state` 到达 `READY_CONTACT` 后，执行接触：

```bash
/usr/bin/python3 -B -m navigation.treasure_cli status
/usr/bin/python3 -B -m navigation.treasure_cli contact
```

只有亲眼看到目标宝箱在官方画面中消失，才执行：

```bash
/usr/bin/python3 -B -m navigation.treasure_cli confirm --disappeared
/usr/bin/python3 -B -m navigation.treasure_cli status
```

确认状态成为 `CONFIRMED`、计数增加且机器狗停稳，再选择下一箱。`WAIT_CONFIRM` 本身不表示宝箱已消失。完整规则见 [宝箱 Ubuntu 手册](../../navigation/TREASURE_UBUNTU.md)。
