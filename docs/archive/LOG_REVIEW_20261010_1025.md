**因此，这不是“第二点已通过但任务丢失”。** 两轮只有一次点击进入导航节点并成功设置中心；第二点没有进入成功或拒绝分支。无法仅凭现有日志区分 RViz 工具退回、实际发布话题不对或第二条消息未送达，不能据此否认操作者确实点了两次。

代码会在第二个有效点被接受时创建任务。即使后续规划失败，任务也会保留为失败状态，不应仍是 null。本次中心点已经通过未知区、隔离区域等检查，没有证据支持增大半径或放宽障碍限制。

## 当前 RViz 里直接处理

1. 打开 **Tool Properties（工具属性）** 面板，展开 **Publish Point**。
2. 核对 Topic 为 `/clicked_point`，取消勾选 **Single click**。
3. 在命令终端重新运行 `/usr/bin/python3 -B -m navigation.treasure_cli status`。
4. 若回合仍为 ACTIVE、`selection.center` 已有坐标且 SDK 没有故障，**只需补点接近点**，不要重新 new-round，也不需要重复中心点。
5. 若 selection 已为空，读取 reason；无故障且停稳后重新 select，再按中心、接近点顺序点两次。SDK 故障须先退出失败导航、恢复仿真通信并带 `--stand-up` 重新启动；回合恢复遵循官方仿真是否仍为同一轮，不能盲目重建计时。
6. 第二点选在距中心 0.55～1.00 米的可达空地，建议约 0.75～1.00 米。
7. 第二点被接受后立刻切回 **Move Camera**，避免第三次点击中断刚启动的接近导航；再查询 status，确认 current_attempt 出现。

若仍未推进，另开相同 ROS 环境的终端进行只读监听：

```bash
ros2 topic echo /clicked_point --qos-reliability best_effort
```

按既定流程进行点选，每次有意的 Publish Point 应出现一份 PointStamped。监听到两份但任务仍空时，记录这两份消息和之后的 status，便可进一步检查话题、坐标与节点接收情况。不要为了监听随意发布第三个目标点。
